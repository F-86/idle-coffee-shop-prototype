# 底栏拖拽与家具闭环：独立浏览器复测

只在独立浏览器 profile / 全新测试 origin 使用，不能导入日常小店。此目录没有部署入口，也不改变游戏运行逻辑。

1. 检出功能分支，`npm ci`，`npm run dev -- --host 127.0.0.1 --port 4192`。打开 `http://127.0.0.1:4192/?qa=1`。用全新 profile/origin，先完成或跳过引导。
2. 全新店：点墙上「装修 / 扩建」，观察清场，从底部“新桌椅”卡片按住拖到合法空地，检查绿/红预览和原因后松手，最后完成，确认扣款一次；红色预览不能完成。取消/Escape 不扣款。直接拖动场景内柜台可以移位；空白处拖动仍逛店，点卡和移动箭头也能选位。
3. 如需快速检查扩建，运行 `node qa/layout/generate-fixtures.mjs /tmp/mellow-bean-layout-qa`，通过设置 → 小店存档 → 选择文件 → 预览 → 明确确认导入合成测试文件。文件名含 QA，虚构已赚余额/40位顾客只用于测试，不是真实用户进度；没有修改生产应用的隐藏加钱入口。
4. `funded-before-renovation` 用于实际添置、旋转、收起/恢复、扩建一次；`expanded-four-counters` 用于观察四柜台与座位；`expanded-in-flight` 用于读档、原位路径和座位恢复；`stored-coffee-and-counter` 用于从收纳拖回拿铁Lv.4和柜台D，同一资产/等级保持。
5. 桌面 1440×960、手机 390×844、横屏 844×390：检查底部横栏不遮满场景、目录可横向浏览，手机横滑卡片不添置、纵向拖出能摆放；四个旋转方向的柜台仍有可见的左选咖啡/右升级实体。不能只看投影坐标，要实际点击和观察像素。
6. 连续观察取杯 → 堂食/外带 → 退出；空椅也不能被路人穿过，经理小推车转角不能穿家具。留意多条路交会、满座及反复收起/放回。
7. 编辑未确认时切后台/返回、刷新、Escape 焦点在设置按钮、同 origin 第二页引起冲突；草稿应取消、原布局/暂停标记保留。导出/导入和正常离线80%沿用同一布局，不在起身离座时重复付款。

`?qa=1`只增加读状态和诊断：`window.__coffeeSliceDebug.readRenovation()`、`readLayoutCell(x,z)`、`readLayoutItem(id)`、`readState()`。这些不是操作或作弊入口。关闭 QA 面板后也要截图普通画面，避免把诊断遮挡当作产品 UI。

记录浏览器/viewport/提交、真实或模拟时长、PASS/FAIL/BLOCKED，保存截图。核心、模拟 DOM、NullEngine 不能替代这个步骤。没有真实设备数据时不声称 Mac/GPU/功耗通过。

装修专项：鼠标从底栏拖新桌椅、已有A柜台、收纳柜台和咖啡牌；墙牌只能落在墙上，重叠/错误高度红色。拖到半途Escape/失焦，回到原草稿且捕获释放；再Escape退出。非法松手、拖后click、重复完成不得增加物件或扣款。初始与完成装修后的地毯/路线箭头均应消失。关闭QA面板分别截图正常经营和底栏装修。
