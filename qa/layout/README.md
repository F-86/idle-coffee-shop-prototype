# 家具闭环：独立浏览器复测

只在独立浏览器 profile / 全新测试 origin 使用，不能导入日常小店。此目录没有部署入口，也不改变游戏运行逻辑。

1. 检出功能分支，`npm ci`，`npm run dev -- --host 127.0.0.1 --port 4182`。打开 `http://127.0.0.1:4182/?qa=1`。用全新 profile/origin，先完成或跳过引导。
2. 全新店：点墙上「装修 / 扩建」，观察清场，再点「＋桌椅」。放到合法处完成，确认扣款一次；红色预览不能完成。取消/Escape 不扣款。拖动镜头和移动箭头都能选位。
3. 如需快速检查扩建，运行 `node qa/layout/generate-fixtures.mjs /tmp/mellow-bean-layout-qa`，通过设置 → 小店存档 → 选择文件 → 预览 → 明确确认导入合成测试文件。文件名含 QA，虚构已赚余额/40位顾客只用于测试，不是真实用户进度；没有修改生产应用的隐藏加钱入口。
4. `funded-before-renovation` 用于实际添置、旋转、收起/恢复、扩建一次；`expanded-four-counters` 用于观察四柜台与座位；`expanded-in-flight` 用于读档、原位路径和座位恢复。
5. 桌面 1440×960、手机 390×844、横屏 844×390：检查托盘不遮满场景，可滚动；四个旋转方向的柜台仍有可见的左选咖啡/右升级实体。不能只看投影坐标，要实际点击和观察像素。
6. 连续观察取杯 → 堂食/外带 → 退出；空椅也不能被路人穿过，经理小推车转角不能穿家具。留意多条路交会、满座及反复收起/放回。
7. 编辑未确认时切后台/返回、刷新、Escape 焦点在设置按钮、同 origin 第二页引起冲突；草稿应取消、原布局/暂停标记保留。导出/导入和正常离线80%沿用同一布局，不在起身离座时重复付款。

`?qa=1`只增加读状态和诊断：`window.__coffeeSliceDebug.readRenovation()`、`readLayoutCell(x,z)`、`readState()`。这些不是操作或作弊入口。关闭 QA 面板后也要截图普通画面，避免把诊断遮挡当作产品 UI。

记录浏览器/viewport/提交、真实或模拟时长、PASS/FAIL/BLOCKED，保存截图。核心、模拟 DOM、NullEngine 不能替代这个步骤。没有真实设备数据时不声称 Mac/GPU/功耗通过。
