# 双门经营与装修：隔离浏览器复测

只在全新 profile / 独立测试 origin 使用，不能导入日常小店。本目录没有部署入口，不改变运行逻辑。

1. `npm ci` 后运行 `npm run dev -- --host 127.0.0.1 --port 4196`，打开 `http://127.0.0.1:4196/?qa=1`。跳过引导并折叠诊断，截图普通店面。
2. 观察店外草地/铺地、右入口/左出口、直接交杯入账；没有经理、推车、金库和墙上咖啡。底部只有有图的咖啡、背景、家具、招客图标。
3. 先点「暂停营业」，再点家具。已有客喝完离开前只显示清场，之后出现独立草稿。拖“新桌椅”到绿区放置，红区/面板上松手取消。点击恢复不能丢草稿；完成一次扣钱一次，仍暂停，需再点恢复才接客。
4. `node qa/layout/generate-fixtures.mjs /tmp/mellow-bean-operations-qa` 生成四个合成文件，经设置→小店存档→预览→确认导入，仅作QA。虚构收入和40名顾客不是真实进度，不能改生产运行代码加钱。
5. 文件分别是 funded-before-renovation（待装修）、expanded-four-counters（扩建四柜台，暂停）、stored-counter-upgraded-coffee（存放柜台D、拿铁Lv4，暂停）、expanded-in-flight（营业中有客）。确认身份/等级保留，扩建出口移到新边界。桌椅座位不能被路人穿过。
6. 桌面1440×960、手机390×844、横屏844×390：面板居中留白，不全宽；每件物品都有图片；鼠标/触摸真实拖动可用，横向浏览不变成购买，旋转后的柜台两个牌都可点。移位、收起、恢复、非法点、半途Escape/失焦、多指和重复完成不得新增资产或扣钱。
7. 暂停后刷新/切后台再回来保持暂停且关闭期间零收益。编辑未确认时切后台/刷新取消草稿、保留原布局与暂停。营业中离线仍按80%模拟。
8. 咖啡图标能切换两配方升级；三种背景只改店外色彩、刷新保留；设置/导入/恢复保护不能自动开门。

`?qa=1`只增加读状态：window.__coffeeSliceDebug.readRenovation() / readLayoutCell(x,z) / readLayoutItem(id) / readState()，无操作或加钱接口。

记录浏览器、viewport、提交、真实或模拟时长、PASS/FAIL/BLOCKED及截图。核心、模拟DOM、NullEngine不可替代浏览器。云浏览器本地origin拒绝时记录BLOCKED，不绕过；Mac/GPU/功耗无数据则不声称通过。
