# 界面与可用性规格

版本：候选 v0.1，draft。

## REQ-UI-001 布局与触控

支持 844×390、667×375、1280×800、390×844，100% 缩放。横屏/桌面关键余额、营业状态和升级入口无遮挡；竖屏允许场景容器横滑，文档本身不能横向溢出。柜台、员工、现金锚点滑动同步；回金库入口可返回左侧。主要点击目标至少 44×44 CSS px，不因相邻控件误触。调整视口不改变经营资产。

## REQ-UI-002 弹窗与键盘

一次只显示一个主弹窗，关闭后恢复原场景。Tab 可到主要动作；弹窗打开焦点进入弹窗、Tab 不穿透背景，Escape 关闭并恢复触发处焦点。按钮有可理解名称；锁定/不足额不只靠颜色表达。滚动和关闭弹窗不触发背景购买。

## REQ-UI-003 状态与数值展示

营业、制作、收款、存入、失败与升级成功提供对应反馈；金额显示与业务精度一致。零、大额、最长名称均不遮挡关键控件；图像资源失败时关键操作和文本仍可用。控制台无因正常操作产生的未处理异常。

## REQ-UI-004 横屏优先场景层级

横屏是店内主体验。844×390、667×375 和桌面视口中，快捷入口、咖啡墙、柜台操作、金库升级和底部收款反馈必须各自保持独立可点击区域，不得发生遮挡或把实时金额压缩成不可辨认的小字；关键状态和金额使用不小于 12px 的 CSS 字号，主要操作目标不小于 44×44 CSS px。390×844 作为兼容布局保留横向场景浏览与旋转提示，但不应产生页面级横向溢出或把核心场景挤出可操作区域。该规格只约束信息层级与可读性，不要求逐像素复刻原作。

## REQ-UI-005 场景世界层与咖啡图标选择

背景、咖啡墙、金库、柜台选择器、柜台、顾客和经理必须挂在同一个可横向浏览的场景世界坐标系中；横向滚动或调整视口时，它们保持相对位置一致，不允许由独立文档流或不同定位基准造成漂移。每种已定义咖啡必须有独立图标；柜台上显示当前咖啡图标，玩家点击图标后打开包含咖啡名称、图标和解锁状态的选择器，选择已解锁咖啡后立即更新该柜台配方，点击选择器不能误触发柜台催促出杯。

## REQ-UI-006 方块人物清晰度

咖啡师、顾客和经理在桌面与 844×390 横屏场景中必须保持可辨认的方块轮廓、服装主色和动作姿态；人物不能因 Canvas 平滑缩放或显示尺寸过小而与背景融合。人物应使用适合低多边形方块素材的硬边渲染，并在不遮挡柜台操作和候客地毯的前提下保留足够的视觉尺寸。

## REQ-UI-007 侧向 2.5D 场景深度

店内主场景采用侧向 2.5D 视角，而不是互相覆盖的平面 2D 卡片：墙面/后场、经理通道、柜台、柜台前向外延伸的候客地毯和前景顾客具有稳定的前后层级。入口在场景左侧、出口在场景右侧；经理推车的巡回通道必须位于柜台与墙之间，顾客不能穿过经理通道或柜台。背景、入口、地毯、角色、柜台和可操作控件必须使用同一 world 坐标基准，角色移动时不得脱离对应设施。

## REQ-UI-008 场景交互入口分层

侧向 2.5D 场景中，三个交互入口必须各自独立且可辨认：点击柜台实体区域打开该柜台详情；点击柜台上的咖啡图标打开配方选择器；点击柜台前向前景延伸的候客地毯催促该柜台当前在制杯。柜台详情至少展示当前配方、当前单价、当前/升级后单价倍率、制作时长、升级价格和升级后的制作时长；咖啡墙项目先打开配方详情，购买或解锁由详情中的明确按钮完成。咖啡图标选择器内的点击不能触发催制作，地毯点击不能误触发配方切换或升级；每次催制作仍遵守 [REQ-PROD-002](operation.md) 的一次性交付与反馈规则。

咖啡墙摘要项同时展示当前咖啡图标、名称、当前等级/锁定状态、当前升级金额和五个升级点；已完成的升级点使用填充状态，未完成或锁定状态使用空心状态。该视觉状态不替代详情弹窗中的可读文字与购买反馈。

## REQ-UI-009 Figma 主场景视觉基线与素材映射

Figma 会话 [主场景画板 `VIEW / Home · v2 · 2.5D integrated`](../design-record-2.5d.md) 的 1280×720 导出是本轮视觉对照基线：墙面菜单板位于上方，固定余额/品牌/加速牌匾位于视口边缘，柜台从左到右排列，柜台前地毯向前景展开，经理通道位于墙与柜台之间，入口在左、出口在右。浏览器实现应使用资产页已提供的咖啡图标、顾客、咖啡师、经理和柜台视觉资产；不得以不属于该基线的照片背景或另一套人物风格替代主场景。

该条只约束视觉目标和素材来源，不自动确认 Figma 中仍标记为候选的 8 柜台、8 配方、价格或解锁表。浏览器在 1280×720 基线状态至少应保持四个可见柜台槽位与八项咖啡墙视觉槽位的构图；业务交互可在当前正式规格覆盖的柜台和配方范围内逐步扩展，未实现的槽位必须明确显示锁定或不可用状态。
