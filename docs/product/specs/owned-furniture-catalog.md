# 同类家具分组与可用库存

2026-10-05 UTC；REQ-3D-043 / TC-3D-030。基线 `af38c0b1aac4055b63316836d06d0f2330413c5d`，任务分支 `codex/owned-furniture-catalog`。

## 已确认范围与库存含义

柜台 A/B 是同类咖啡柜台，不再各占一张目录图片卡；桌椅同样按类型分组。分组只改变装修目录和选择方式，不合并资产身份、不重置升级，也不把摆放已拥有家具解释为购买。

目录中的「可用」是当前装修草稿内尚未放置的实例数量；已经放进店里的实例不再计入可用，但仍可在场景中选中、移动和收起。已付款拥有量与待购量分开表达，不把尚未完成的购买写成已经拥有。可用数量可包括明确标记的待购实例，便于购买后再决定位置。

## 验收行为

- REQ-3D-043.1：全部分类至多显示一张有图「咖啡柜台」卡和一张有图「桌椅」卡；类型分类和收纳分类沿用相同分组方式。卡片显示当前可用数量，并区分已拥有、已放置及待购状态；没有按 A/B 或每个实例重复的图片卡。
- REQ-3D-043.2：有可用实例时，点击或拖出类型卡只选择/放置该实例，不新增资产、不产生购买费用。成功放置一件使可用数量减一；仅按住、选择、未完成预览、非法松手或取消拖动不能永久消耗库存。放置已拥有家具前后，钱包、支出、拥有总数和实例身份不变。
- REQ-3D-043.3：只有该类型可用数为零时，卡片右上角才可提供独立的「购买 + 价格」入口。点击卡片主体或拖动空库存卡不能代替购买。明确购买先加入一件收纳中的待购草稿实例，可用数立即变为一，购买入口随即隐藏；放置该实例仍使用同一张类型卡。余额/容量不足不能新增候选；重复或过期输入不能绕过库存门禁。
- REQ-3D-043.4：待购物件直到有效「完成布置」才成为已拥有资产，并按草稿中仍保留的待购项一次性扣款。选中待购项后可取消该项；取消整次装修、Escape 退出、隐藏/离页、存档冲突等既有事务中断丢弃全部未提交购买，不扣款。编辑中的保存不纳入草稿；重复完成不能多次扣款。
- REQ-3D-043.5：收起已拥有家具立即增加当前草稿可用数，原来显示的购买入口消失；再次放回使用原实例，费用为零。仍遵守至少保留一个放置柜台、合法占地和动线等约束。完成后重新装修、保存/读回均保留正确库存；取消则恢复进入本次装修前的布局与数量。
- REQ-3D-043.6：柜台实例保留原 `id` / `counterId`、等级、当前配方、固有亲和效果及生产记录。存在多个可用柜台时，只有等级、配方或固有亲和效果等实际差异才显示紧凑文字选择器；同等实例可稳定自动选择，不要求逐个展开。A/B 即使等级与当前配方相同，也因固有亲和效果不同而不能被视为等价。选择器不另建多张图片卡；可用的已付款实例优先于待购实例。
- REQ-3D-043.7：桌椅遵守相同的数量递减、收起补回、零库存明确购买及延期扣款规则；没有实际差异的桌椅不强制出现实例选择器。拖后 click、次要指针、捕获丢失、失焦、横向浏览与键盘替代操作沿用原保护，不重复放置或误购。
- REQ-3D-043.8：保持已修复的取消/完成操作行，窄屏文字完整且所有控制可达。新购买入口与数量不互相遮挡，库存为零的卡片不呈现可免费放置的误导状态；价格、按钮状态和可访问名称能明确区分摆放与购买。

## 不变边界

当前经济5、布局3、手动文件5及离线规则不因目录分组而升级；不新增经济平衡、柜台类别、咖啡配方、赠送家具或付费加成。沿用当前家具价格与容量上限，数值仍为 draft。完成或取消装修后保持暂停，恢复营业仍需明确操作。

本规格替代 REQ-3D-036/039 中按单件柜台和独立「新家具」图片卡展示的部分，其他拖拽、布局、暂停与保存保护继续适用。正常提交/推送仅限本任务分支；本轮不授权合并 main、部署或修改部署配置。自动化与真实浏览器验收分开记录。
