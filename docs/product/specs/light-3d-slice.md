# 轻量 3D 可玩闭环 v0.1

2026-10-03。范围依据：用户委托在云端开发、接近 Idle Coffee Corp 的经营构图与操作感，并允许独立优化后期膨胀。两个柜台、两种咖啡、一名经理是本轮可验收单元。以下精确数值为可调整的 draft 调参，不冒充用户认可的商业平衡。

- REQ-3D-001 accepted：用户允许清空旧代码；默认入口使用新的纯 TypeScript / Babylon 架构，旧版仅保留在 Git 历史。新版本用原创低多边形角色、固定斜俯视、菜单后墙、木柜台、彩色纵深排队通道；参考游戏宣传图仅研究，不直接打包。
- REQ-3D-002 accepted：顾客进入、选柜台、排队前移、制作、交杯、带杯离店；钱先留在对应台面，再被经理沿柜台后方收走，送回金库才计入可用余额。经理转移不能重复创造钱。
- REQ-3D-003 accepted：入口招客、柜台升级、菜单换配方都是可用动作；两配方具备速度/杯价取舍，升级预览显示收益与回本时间。制作开始时快照杯价/时长，不追改已有杯子。
- REQ-3D-004 accepted：模拟完全独立于渲染；固定时间步与确定性序列，重复输入有冷却/成本/上限检查。暂停冻结模拟，恢复不补发暂停时间。
- REQ-3D-005 accepted：手机采用可以横向平移的店铺视口和足够大的触控控件，而非把完整店面缩成难点的小画布。桌面和移动端辅助操作同样可达。
- REQ-3D-006 accepted：新版本独立版本化本地存档，不承担旧版迁移或兼容。验证 schema、枚举、有限数字与资产边界；坏档/未来版本要明确提示并保留原字节。离线收益一次结算、不重复领取。
- REQ-3D-007 accepted：提供 AuthProvider / SaveRepository 边界与 CAS、幂等、双客户端离线冲突测试。iCloud/CloudKit 是目标适配方向；未提供 Apple container/环境/账户配置时明确“未配置”，不创建账号或声称实际跨设备同步。
- REQ-3D-008 draft：升级最多 20 级，单次成长渐进；取消无上限的全局乘区和广告依赖。报告实测收入集中度、最大回本时间与经理收运瓶颈，而非只修改数字缩写。

离线暂定规则：最多 2 小时，经营暂停为 0；与在线使用同一闭环按 0.5 收益效率推进，存档的结算锚点随结算写回。此数值是可调整提案。金额最小单位为分，UI 使用 ¥ 符号显示虚拟咖啡金额，不代表真实支付。

## 全屏场景修订（2026-10-03）

- REQ-3D-009 accepted，用户观看真实Mac截图后的明确反馈：整个屏幕应是场景。默认页面为100vw×100dvh店铺，没有网页页头、经营卡片、常驻侧栏或页面纵向滚动。HUD仅余额、暂停与设置等小控件（后续REQ-3D-013收紧为仅余额）。
- REQ-3D-010 accepted：墙面两种咖啡菜单、墙上金库、柜台配方选择器与升级牌、入口和经理都在店内。触控操作与物件使用同一worldanchor投影，不随镜头漂移（后续REQ-3D-013/014改为纯实体几何拾取，取消DOM浮层）。原有两配方均已解锁，不新增研发/购买规则。
- REQ-3D-011 accepted：真实viewport画布与受限镜头平移，竖屏局部观察后拖动逛店；不得为了看全而缩成小型置中diorama。房间地面/墙体填充背景，相机初始区域包括可玩的柜台，不从大片空白开始。
- REQ-3D-012 accepted：操作弹窗仅按需打开，关闭按钮/背景/ Escape可回店，不存在常驻经营面板。触控至少44px，safe-area与dvh变化适配，拖动/长按/取消不误触，开窗时背景不可点击。

这次只改布局、镜头、交互入口与表现，经济、离线、存档schema、CloudKit范围不变。


## 实体嵌入操作修订（2026-10-03）

用户观看真实全屏版截图后认可整体方向，但明确墙上咖啡和柜台选择器依旧像HUD。最新要求覆盖之前允许常驻worldanchor DOM触控按钮的表现方案。

- REQ-3D-013 accepted：常驻HUD只有当前金额，明确以¥显示。墙面咖啡菜单、金库、营业暂停/继续牌、设置物件，柜台配方选择/升级、入口招客及经理操作都由真实3D几何承载。永久投影DOM按钮全部删除；物件文字贴在实体表面，保留固定斜俯视的透视缩短、光照和正常深度遮挡，不用alwaysOnTop、billboard或透明点击箱假装实体。
- REQ-3D-014 accepted：只点击当前视角真正可见的前方实体，不穿过人物、家具或其他遮挡触发后方按钮。相同画布内统一捕获按压/拖动/长按/取消；移动目标要核对按下/抬起对象一致。可平移到每个入口，聚焦后的实际几何目标至少44 CSS像素且可读；键盘可选择/平移/激活真实物件，没有额外常驻网页工具栏。
- REQ-3D-015 accepted：维持全屏大店铺构图和手机局部逛店，横屏墙面菜单和营业/设置物件通过受限pan可达。详细管理UI仅点击后弹窗，关闭后回场景；名字提示仅操作需要时瞬时出现。资金链、经济数值、存档schema及离线/iCloud范围完全不变；独立真实三尺寸截图和玩家操作仍是视觉验收依据。


## 金库与柜台前脸修订（2026-10-03）

用户已打开Mac预览后明确更新布局：设置可以进HUD、不要暂停按钮，经理等级放金库，金库在所有咖啡面板左侧，咖啡选择器贴柜台前面，金额放钱的位置。以下覆盖前一轮对应的入口/位置要求。

- REQ-3D-016 accepted：HUD为¥当前金额+设置，没有玩家暂停按钮/墙牌/设置项/热键或隐藏入口。保留核心暂停机制用于存档冲突等技术保护。来自之前有效暂停档的离线区间仍按暂停档结算0，随后自动恢复当前可玩营业；冲突/离线端点写失败不能被这个恢复逻辑解锁。
- REQ-3D-017 accepted：金库在画面所有咖啡菜单的左侧，经理等级显示在金库实体上；金库弹窗同时负责经理等级、收运效率和升级。删除独立经理窗口/推车操作牌，普通推车只表现搬运。镜头三个viewport和pan仍可到金库与菜单，不用坐标系的“worldX左”混淆玩家看到的“画面左”。
- REQ-3D-018 accepted：两柜台配方选择器贴前脸，和升级牌各自是真实表面、光照/深度/拾取，不搭立在台面的框牌。待收金额直接绑定纸钞区域，随真实现金显示，不使用柜台上方的高收银牌。可读可点几何目标仍满足44px，顾客正常遮挡但不能永久遮住唯一入口。

经理路线用渲染层将原有分段进度映射到新的可视金库位置，三个停靠点连续，送款时实际抵达金库。纯core坐标/速度/容量/时长、金额、经济、存档schema和离线规则全部不变；展示收运效率按Lv.1基准百分比，不把重新映射的可视米数冒充核心速度。原来已明确允许无旧版兼容，本条只处理当前schema的正常暂停状态，不导入旧版档。
