# 轻量 3D 可玩闭环 v0.1

2026-10-03。范围依据：用户委托在云端开发、接近 Idle Coffee Corp 的经营构图与操作感，并允许独立优化后期膨胀。两个柜台、两种咖啡、一名经理是本轮可验收单元。以下精确数值为可调整的 draft 调参，不冒充用户认可的商业平衡。

- REQ-3D-001 accepted：用户允许清空旧代码；默认入口使用新的纯 TypeScript / Babylon 架构，旧版仅保留在 Git 历史。新版本用原创低多边形角色、固定斜俯视、菜单后墙、木柜台、彩色纵深排队通道；参考游戏宣传图仅研究，不直接打包。
- REQ-3D-002 accepted：顾客进入、选柜台、排队前移、制作、交杯、带杯离店；钱先留在对应台面，再被经理沿柜台后方收走，送回金库才计入可用余额。经理转移不能重复创造钱。
- REQ-3D-003 accepted：入口招客、柜台升级、菜单换配方都是可用动作；两配方具备速度/杯价取舍，升级预览显示收益与回本时间。制作开始时快照杯价/时长，不追改已有杯子。
- REQ-3D-004 accepted：模拟完全独立于渲染；固定时间步与确定性序列，重复输入有冷却/成本/上限检查。暂停冻结模拟，恢复不补发暂停时间。
- REQ-3D-005 accepted：手机采用可以横向平移的店铺视口和足够大的触控控件，而非把完整店面缩成难点的小画布。桌面和移动端辅助操作同样可达。
- REQ-3D-006 accepted：新版本独立版本化本地存档，不承担旧版迁移或兼容。验证 schema、枚举、有限数字与资产边界；坏档/未来版本要明确提示并保留原字节。离线收益一次结算、不重复领取。
- REQ-3D-007 accepted：提供 AuthProvider / SaveRepository 边界与 CAS、幂等、双客户端离线冲突测试。iCloud/CloudKit 是目标适配方向；未提供 Apple container/环境/账户配置时明确“未配置”，不创建账号或声称实际跨设备同步。
- REQ-3D-008 draft：升级最多 20 级，单次成长渐进；取消无上限的全局乘区和广告依赖。报告实测收入集中度、最大回本时间与经理收运瓶颈，而非只修改数字缩写。

离线暂定规则：最多 2 小时，经营暂停为 0；与在线使用同一闭环按 0.5 收益效率推进，存档的结算锚点随结算写回。此数值是可调整提案。金额最小单位为分，UI 显示币。

## 全屏场景修订（2026-10-03）

- REQ-3D-009 accepted，用户观看真实Mac截图后的明确反馈：整个屏幕应是场景。默认页面为100vw×100dvh店铺，没有网页页头、经营卡片、常驻侧栏或页面纵向滚动。HUD仅余额、暂停与设置等小控件。
- REQ-3D-010 accepted：墙面两种咖啡菜单、墙上金库、柜台配方选择器与升级牌、入口和经理都在店内。可访问的触控按钮与物件使用同一worldanchor投影，不随镜头漂移。原有两配方均已解锁，不新增研发/购买规则。
- REQ-3D-011 accepted：真实viewport画布与受限镜头平移，竖屏局部观察后拖动逛店；不得为了看全而缩成小型置中diorama。房间地面/墙体填充背景，相机初始区域包括可玩的柜台，不从大片空白开始。
- REQ-3D-012 accepted：操作弹窗仅按需打开，关闭按钮/背景/ Escape可回店，不存在常驻经营面板。触控至少44px，safe-area与dvh变化适配，拖动/长按/取消不误触，开窗时背景不可点击。

这次只改布局、镜头、交互入口与表现，经济、离线、存档schema、CloudKit范围不变。
