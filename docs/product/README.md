# 产品目标与功能地图

目标：开发参考放置咖啡店经营玩法的浏览器游戏，使用 Mellow Bean 的原创名称与视觉；玩家通过经营、自动生产、收款、升级和扩张获得持续成长。

测试范围由最终产品行为确定，当前原型用于记录实现进度。以下功能地图是规划起点，具体范围和规则逐项确认，不代表全部已经承诺或实现。

相关设计来源：[2.5D 主场景产品设计记录](design-record-2.5d.md)。该记录整理指定 Figma 会话中的视觉方向、交互入口、取舍和验证边界，不替代下面的行为规格。

| 功能域 | 拟覆盖的最终体验 | 待明确事项 |
| --- | --- | --- |
| 初次进入与引导 | 玩家理解生产、收款、升级循环 | 新手初始资源、引导方式 |
| 自动经营 | 柜台、咖啡师、顾客队列、制作与交付 | 产能与实际顾客的关系、队列容量 |
| 收款与经济 | 待收现金、经理运输、金库、消费 | 结算时点、精度、容量与收益公式 |
| 柜台互动催制作 | 点击柜台前候客地毯加急当前在制杯、交付、待收反馈；点击柜台实体查看详情 | 催制作是否消耗资源；当前沿用无消耗假设 |
| 配方与设备 | 解锁、选择、升级、效果反馈 | 价格表、等级上限、效果公式 |
| 员工与经营升级 | 招募、分配、效率提升 | 分配规则、成本和上限 |
| 成长与分店 | 目标奖励、解锁地点、切换经营 | 共享资源、分店并行收益规则 |
| 放置与离线 | 离开后收益、重返说明与结算 | 时长上限、倍率、打烊行为 |
| 存档与恢复 | 刷新恢复、重置、异常存档恢复 | 保存字段、兼容策略、多标签行为 |
| 界面与可用性 | 可读、可操作、状态反馈、适配 | 横竖屏目标、键盘与触控验收范围 |

库存、原料消耗、支付、广告、账号、云存档、多人玩法目前均未确认为最终范围。不要从通用咖啡店测试模板自动引入这些系统。

下一步按 [行为规格](requirements.md) 的格式展开各域，并更新 [覆盖矩阵](../testing/coverage.md)。数值需包含单位、精度、边界、舍入方式和时间语义。
