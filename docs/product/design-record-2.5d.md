## 记录用途

本文件从指定会话中提炼产品设计意图、视觉结构、交互入口和验证边界。会话中后续的用户反馈覆盖较早的尝试；以下以较晚、较明确的表达为准。

这是一份设计来源记录，不替代行为规格、数值契约或浏览器验收结果。业务规则仍以[候选基线](baseline.md)、[设计决策清单](decisions.md)和 `docs/product/specs/` 为准；视觉方向若要成为正式产品要求，仍需单独确认并更新对应需求与用例。

## 方向摘要

主场景采用侧向 2.5D 的咖啡店空间，而不是互相覆盖的平面卡片。玩家从左侧进入，沿柜台前的候客地毯看到柜台和顾客，顾客交付或满位后向右侧出口离店；经理在墙与柜台之间的后场通道巡回。

场景世界和视口 HUD 分层如下：

```text
固定 HUD（随视口固定）
├─ 当前余额（不是“今日收入”）
├─ 当前店铺名称/街区
└─ 咖啡加速状态（紧凑展示，不显示“点击续杯”）

可横向浏览的场景 world
├─ 后墙、侧墙、室内地面与室外路面
├─ 墙面菜单板与左下方金库图标
├─ 墙与柜台之间的经理通道
├─ 带台面厚度和侧面的柜台
├─ 柜台前向前景延伸的透视候客地毯
└─ 顾客、咖啡师、经理及其他场景角色
```

## 已覆盖与被后续方案替代的选择

会话中有几次结构方向调整，记录如下，避免把早期草稿误当成最终方向：

| 早期尝试 | 后续方向 |
| --- | --- |
| 4×2 柜台或前后两排 | 8 个柜台改为同一条从左到右的横向柜台带，纳入可横向浏览的 world |
| 入口/出口作为场景上方的按钮 | 入口/出口嵌入墙体和地面边界，允许门洞、门槛、墙厚和室外铺装共同表达 |
| 柜台长期显示完整信息卡 | 常态只显示圆角矩形咖啡图标，详细信息在点击后的状态中显示 |
| 底部营业栏和“营业中”按钮 | 店铺默认常驻营业，取消底部营业栏，将加速放进紧凑 HUD |
| 余额/店铺/加速全部作为墙面内容，或全部作为场景装饰 | 采用固定 HUD 与场景 world 的分层；金库和菜单板仍属于场景，余额/当前店铺/加速固定 |
| 右侧实体墙封闭场景 | 保留右侧开放边界，出口成为顾客离店的场景端点 |

## 会话中报告的 Figma 交付结果

以下是会话中助手报告的结果，仅作为设计历史证据，不代表本仓库当前实现或正式产品验收已经通过。

### 已完成或已反复修正的部分

- 将 `VIEW / Home · v2 · 2.5D integrated` 从高分辨率场景图参考逐步拆为可编辑的原生图层、矢量和组件。
- 建立后墙、透视地面、带厚度的柜台、柜台前地毯、经理后场通道、左侧入口和右侧开放出口。
- 对左墙厚度、透明门洞、门洞后的室外路面、墙脚连续转角、地面接缝覆盖范围和室外透视做了多轮局部修正。
- 组件化柜台、咖啡图标、地毯、入口/出口和角色；将 `Counter / Interaction State` 作为可复用状态组件集，并区分状态参考板与真正的组件源。
- 旧稿、旧图层和旧素材采用隐藏/归档方式保留，没有用破坏性删除覆盖回退参考。

### 会话中明确保留的占位或未完成项

- 角色和咖啡图标内部仍有简化的原生矢量、杯子 glyph 或现有插图占位，尚非最终美术资产。
- 本轮浏览器实现可直接复用资产页导出的 `Coffee icon / Counter / Actor` 组件 PNG；导出文件应保留来源节点 ID 和尺寸记录，不得用照片场景或另一套人物素材替代 Figma 视觉基线。
- 柜台解锁、咖啡解锁、升级和切换在部分画板中是静态状态示意，不等同于已配置完整交互逻辑。
- Local Bridge 当时不能直接写入全部 Figma Prototype 连线，因此三个柜台交互状态已建立，但连线仍需在 Prototype 面板中补接。
- 横向真实拖动滚动在会话部分阶段受工具能力影响，未作为 Figma 原型的完整回归证据；静态 1280×720 导出不能替代浏览器和 Prototype 验收。
- 某些文字自动溢出审计曾超时，后续以导出图和可见文字人工检查为补充，不能把这类轮次记为自动审计通过。

## 会话中报告的验证边界

- 工具边界：按用户要求使用本地 Figma MCP Bridge，没有调用云端 Figma MCP；多轮最终状态报告为连接正常、活动插件 1 个、待处理命令 0。
- 视觉检查：导出并检查过 1280×720 主场景，以及墙角、门洞、金库和状态组件的局部图；检查项包括图层层级、对齐、文字可见性、遮挡和 2.5D 透视。
