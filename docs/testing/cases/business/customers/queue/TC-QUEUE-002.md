# 顾客从左侧入口进入候客地毯并从右侧出口离店补位

## 目标与依据

验证顾客的可见动线与核心队列保持一致。规则：[REQ-QUEUE-001](../../../../../product/specs/operation.md)、[REQ-QUEUE-002](../../../../../product/specs/operation.md)，候选 v0.1；实现状态未知，本文件不是执行结果。

## 前置条件与参数

- 独立初始化：一号柜台已解锁、有咖啡师和可服务顾客；记录一号柜台显示的队列容量与当前人数。
- 参数实例：桌面 1280×800、横屏 844×390；至少观察一次入店、取杯和新客补位。
- fixture：FX-QUEUE，准备与能力要求见 [共享手册](../../../../shared/fixtures.md)。

## 操作与预期

| 步骤 | AI 通过 UI 执行的操作 | 可观察预期 |
| --- | --- | --- |
| 1 | 营业后连续观察一号柜台队列 | 顾客从场景左侧门口进入，移动到一号柜台向外延伸的候客地毯站位；候客区显示当前人数/容量，站位数量不超过容量。 |
| 2 | 点击一号柜台催促出杯，观察取杯反馈 | 队首顾客在柜台前取杯后沿右侧出口方向离店；旧顾客离场期间不瞬移回队列，出杯业务事件只发生一次。 |
| 3 | 等待补位完成 | 新顾客再次从左侧入口进入，移动到空出的地毯站位；业务队列人数仍不超过容量，其他柜台顾客不串线。 |

## 等待与通过条件

普通 UI 状态变化最长观察 10 秒；动态过程保存连续截图或操作轨迹。全部断言满足才 PASS；环境无法提供稳定入口/队列证据记 BLOCKED，不把静态站位当作动画通过。

## 证据与清理

保存入口、候客地毯、取杯离店和补位时刻截图；记录实际容量、队列人数和控制台日志。移除时间/网络/存储模拟，关闭额外标签页，重置独立测试档。
