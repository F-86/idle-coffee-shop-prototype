# 场景世界层与咖啡图标选择器

## 目标与依据

验证横屏主场景的坐标层级、侧向 2.5D 动线、咖啡图标识别和柜台配方切换。规则：[REQ-UI-004](../../../../product/specs/interface.md)、[REQ-UI-005](../../../../product/specs/interface.md)、[REQ-UI-007](../../../../product/specs/interface.md)，候选 v0.1；实现状态未知，本文件不是执行结果。

## 前置条件与参数

- 独立初始化：至少一号柜台已解锁；至少两种咖啡已解锁，或者记录锁定选项的禁用状态。
- 参数实例：1280×800、844×390、390×844；100% 缩放。

## 操作与预期

| 步骤 | AI 通过 UI 执行的操作 | 可观察预期 |
| --- | --- | --- |
| 1 | 检查背景、咖啡墙、金库、柜台、入口/出口、地毯、经理和 Phaser 角色的位置/父级 | 它们属于同一个场景 world；入口在左、出口在右，地毯从柜台前缘向前景延伸，经理通道位于柜台与墙之间；横屏或竖屏横滑时相对位置同步，页面本身不发生横向溢出。 |
| 2 | 点击一号柜台当前咖啡图标 | 打开选择器；每个选项同时显示咖啡图标和完整名称，当前选中项明确，未解锁项不可选择。 |
| 3 | 选择另一种已解锁咖啡，再点击图标区域 | 柜台当前图标和状态名称更新；切换动作不触发催促出杯，不打开订单弹窗；柜台、地毯和人物仍保持同一侧向深度关系。 |
| 4 | 点击选择器外部或按 Escape | 选择器关闭，场景仍可操作；控制台无 warn/error。 |

## 等待与通过条件

每个视口最长观察 10 秒；主要触控目标至少 44×44 CSS px。全部断言满足才 PASS；无法获取层级或动态横滑证据记 BLOCKED。

## 证据与清理

保存桌面、横屏和竖屏场景截图，以及选择器打开/切换截图；记录父级、矩形、字号、选项名称和控制台日志。移除额外存档与测试状态。
