# 横屏优先场景层级与文字可读性

## 目标与依据

验证横屏店内场景的主要操作互不遮挡、实时金额可读，并确认竖屏兼容布局仍然可滑动。规则：[REQ-UI-004](../../../../product/specs/interface.md)，候选 v0.1；实现状态未知，本文件不是执行结果。

## 前置条件与参数

- 独立测试 origin，使用包含已解锁柜台、顾客、制作进度和待收现金的丰富场景；业务状态通过 UI 或批准的 fixture 准备，不能用默认余额代替 Q1 预期。
- 参数实例：844×390；667×375；1280×800；390×844。每个视口独立观察，100% 缩放。
- 记录快捷入口、咖啡墙、至少一张柜台卡、金库入口、底部收款条的矩形位置、关键文字 CSS 字号、主要按钮尺寸和页面/场景溢出状态。

## 操作与预期

| 步骤 | AI 通过 UI 执行的操作 | 可观察预期 |
| --- | --- | --- |
| 1 | 在每个视口打开店内场景并等待一杯进入制作或待收 | 横屏快捷入口、咖啡墙、柜台和金库不互相遮挡；制作、待收、营业和等级文字可读。 |
| 2 | 点击可负担的主要入口或柜台操作；在竖屏横向滑动场景 | 点击目标至少 44×44 CSS px；横滑只移动场景 world，不改变余额/生产状态；页面本身不产生横向溢出。 |
| 3 | 观察经理沿路线和底部收款反馈 | 收款条仍可见，经理/现金反馈不覆盖柜台操作，控制台没有正常操作产生的 warn/error。 |

## 通过条件

全部参数实例满足：横屏主要层级没有矩形交叠造成的控件遮挡；关键实时文字字号不小于 12px；主要按钮不小于 44×44px；390×844 的文档宽度不大于视口且场景 world 仍可横向浏览；实际 UI 操作成功且资产没有因布局变化异常改变。

## 证据与清理

保存每个视口的截图或可复核矩形/字号读数、控制台日志和操作前后状态。每个实例使用独立 origin 或独立重置后的测试档；结束后移除临时视口覆盖并关闭额外标签页。

## 待决策

不约束正式生产数值、柜台容量或美术资产；这些仍以候选规格和产品决策中的 draft 标记为准。
