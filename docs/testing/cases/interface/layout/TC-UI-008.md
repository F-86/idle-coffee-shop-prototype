# Figma 2.5D 主场景视觉基线与素材一致性

## 目标与依据

验证浏览器实现与 Figma 画板 `VIEW / Home · v2 · 2.5D integrated` 的同状态视觉关系。设计来源、资产页和未完成边界见 [2.5D 主场景产品设计记录](../../../../product/design-record-2.5d.md)；本用例是候选视觉差距测试，不是用户确认的逐像素发布标准。

## 前置条件与参数

- 独立测试 origin，使用仓库内映射自 Figma 资产页的场景、咖啡图标、柜台和角色素材。
- 参数实例：1280×720，100% 缩放；另在 844×390 横屏和 390×844 竖屏检查裁切与可操作性。
- 默认视觉状态：墙面菜单板可见，四个柜台槽位可见，前景地毯可见，入口/出口和经理后场通道可见；业务状态沿用实际 UI 读数。

## 操作与预期

| 步骤 | AI 通过 UI 执行的操作 | 可观察预期 |
| --- | --- | --- |
| 1 | 在 1280×720 打开主场景并保存实现截图 | 画面主构图与 Figma 基线保持同一空间关系：墙面菜单板、四个柜台、前景地毯、经理通道、左入口和右出口均在同一 world 内。 |
| 2 | 放大查看咖啡图标、顾客、咖啡师、经理和柜台 | 资产主体、硬边轮廓、透明边界、主色和比例来自 Figma 映射资产；不出现照片背景与像素人物混用造成的明显风格漂移。 |
| 3 | 打开柜台详情、配方选择器和一个咖啡墙详情 | 动态控件覆盖在对应视觉槽位上，不改变墙/柜台/地毯的前后层级；文字、颜色和按钮状态仍可读。 |
| 4 | 调整到 844×390 与 390×844，并横向浏览场景 | 不产生页面级横向溢出；主场景允许 world 横滑，固定 HUD 与可操作入口不被裁切或遮挡。 |

## 通过条件

必须保存 1280×720 全景和至少一个重点区域对照证据，并逐项检查字体/字号、间距/布局、颜色/视觉 token、图像质量/素材来源、应用文案、交互状态与可访问性。发现 P0/P1/P2 差异时先记为未通过，修复后在同一视口和状态复测；无法打开 Figma 源或实现截图时记 BLOCKED。

## 证据与清理

记录 Figma 源节点 ID、源图像尺寸、实现截图尺寸、CSS 视口、devicePixelRatio、实现路径和控制台日志。结束后关闭额外页面并清理测试 origin 存档。

## 规则状态

视觉方向与素材来源来自明确的 Figma 会话；8 柜台/8 配方、精确文案和商业数值仍按设计记录与产品参数的 draft 边界处理，未声称用户已确认。
