# 2.5D 场景交互入口分层与升级预览

## 目标与依据

验证柜台详情、咖啡图标选择器、候客地毯催制作和咖啡墙详情购买分别绑定到正确的 world 入口。规则：[REQ-UI-008](../../../../product/specs/interface.md)、[REQ-PROD-002](../../../../product/specs/operation.md)、[REQ-RECIPE-001](../../../../product/specs/progression.md)、[REQ-RECIPE-002](../../../../product/specs/progression.md)；候选基线，当前用例不是最终产品验收结论。

## 前置条件与参数

- 独立测试 origin；至少一号柜台已解锁并有咖啡师，队列中有顾客且当前有在制杯。
- 至少两种配方已解锁；记录柜台当前等级、当前配方、余额、制作进度和待收现金。
- 参数实例：1280×800、844×390、390×844；100% 缩放。

## 操作与预期

| 步骤 | AI 通过 UI 执行的操作 | 可观察预期 |
| --- | --- | --- |
| 1 | 点击柜台实体区域 | 只打开该柜台详情；详情展示当前/升级后单价倍率、升级价格和当前/升级后制作时长；不改变生产、余额或待收。 |
| 2 | 关闭详情，点击柜台上的当前咖啡图标 | 只打开配方选择器；选择器显示图标、完整名称和解锁状态，点击选择器不会催制作。 |
| 3 | 选择另一种已解锁配方，再观察当前杯 | 柜台图标和下一杯预览更新；正在制作的当前杯仍按旧配方完成，余额与待收不因打开/关闭选择器改变。 |
| 4 | 关闭选择器，点击同一柜台前的候客地毯一次 | 当前在制杯立即完成并最多交付一次，产生一笔待收现金和可理解反馈；点击选择器、升级按钮或柜台详情不会被误触发。 |
| 5 | 在同一杯已完成后重复点击地毯，并点击咖啡墙项目 | 重复点击不重复产生同一笔收入；咖啡墙摘要显示图标、名称、等级/锁定状态、升级金额和五个升级点；点击项目先显示配方详情，只有点击详情中的购买/解锁按钮才扣款或升级。 |

## 候客层命中回归（2026-10-02）

在 844×390 以及桌面/竖屏实例中额外检查：

- `scene-customer-lanes` 的实际边界与所属 `scene-world` 重合，子地毯位置按完整 world 计算，不能沿用旧队列带的高度。
- 通过正常指针点击咖啡墙“查看美式详情”，不得使用 force 或直接业务调用；只打开美式详情，不能产生 `counter-rushed` 事件。
- 关闭详情后通过正常指针点击一号柜台前地毯，仍触发该柜台催制作；不打开配方详情。用只读测试事件记录区分后台自动产出与点击事件。
- 保存菜单中心和地毯中心的实际命中元素、world/候客容器/子地毯矩形以及操作前后截图；容器透明空白不能阻挡菜单。

## 等待与通过条件

每个视口最长观察 10 秒；主要触控目标至少 44×44 CSS px。全部入口均可通过真实 UI 到达，入口之间没有意外交叉，且状态变化符合业务规则才通过；无法获取动态横滑或事件顺序证据记 BLOCKED。

## 证据与清理

保存桌面、横屏和竖屏截图，记录详情/选择器的可见文本、关键矩形、余额、待收、制作进度及控制台日志。每个实例使用独立 origin 或独立测试档；结束后关闭详情/选择器并移除临时视口覆盖。
