# TC-3D-030 分组家具、库存与明确购买

需求：REQ-3D-043。继续回归 TC-3D-025～029 的安全布局、拖拽、暂停、原料和操作行。

前置：隔离浏览器/profile，独立测试存档与本分支版本；暂停并安全清场。合成档至少保留一个放置柜台，另有两件同类收纳家具；记录进入装修前的钱包、支出、拥有实例 ID 和柜台属性。分别对柜台、桌椅执行库存流程。

1. 全部目录只有一张「咖啡柜台」图片卡和一张「桌椅」图片卡，没有分开的 A/B 或新家具图片卡。分类/收纳仍按类型聚合，数量能区分可用、放置、已拥有与待购；可用数不把已经摆进店的物件算进去。
2. 从可用数二开始，点击/拖出一件并合法放下，数量变一；再放一件变零。钱包、支出、已拥有总数不变，场景出现原来的两件实例。只选中、拖到红区/面板/画布外松手或中断拖动后，库存恢复到该次拖动前。
3. 有库存时没有购买入口；库存零时只在卡片右上角出现明确购买及价格。点击卡片主体、从空卡拖出均不购买。点购买只生成一个收纳的待购实例，数量变一、入口消失，钱包暂不变；连续/过期点击不能继续购买。
4. 从同一张卡放置待购实例，保持原待购 ID，没有生成第二件；费用只包含一件。取消该待购项移除其费用；再次购买后取消整次装修，布局、拥有量、钱包和支出回到进入装修前。有效完成只扣一次；重复完成不再扣款。明确购买后未摆放而直接完成的实例应作为收纳资产保存，并只计费一次。
5. 收起已拥有物件使可用数即时加一、购买入口消失；再放回数量减一，使用原 ID 且免费。取消整次装修恢复原数量；完成并刷新/重新装修后仍正确。最后一个放置柜台不可被收起，不得虚增可用数。
6. A/B 均可用时，出现紧凑文字选择器，能看懂等级、配方和固有亲和差异。选择升级过的指定实例，摆放、旋转、收起和读回后核对 ID、等级、配方、亲和和生产记录未变。将 A/B 设为相同等级/配方仍需保留其亲和差异；等价 C/D 或普通桌椅无需强制选择。已付款可用实例优先于待购库存。
7. 余额不足/家具上限不能添置；旧节点或重复事件不能绕过可用库存、余额或容量。拖后 click、迟到松手和双击不得变成第二次放置/购买；次要指针、横滑、捕获丢失与失焦保持原保护。
8. Escape 先取消正在拖的预览，再退出装修；隐藏/刷新/存档冲突丢弃未提交布局与待购项。完成与取消都保持暂停，不擅自恢复营业；编辑时自动保存不混入草稿。
9. 在 1180×757、1440×960、390×844、320×568、844×390 检查卡片图片、库存数字、右上角价格和选择器不遮挡；取消/完成文字不逐字换行。窄屏允许滚动但全部控制可达。实际鼠标拖拽、触屏横滑/纵向拉出和键盘路径分别记录。
