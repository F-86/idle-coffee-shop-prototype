# TC-3D-019：失败恢复不重置、不覆盖

对应 REQ-3D-029。核心测试和实际 main handler 的假DOM测试使用隔离内存存储、模拟时钟，不是用户浏览器或像素验收。

1. 合法店经理携带570分且totalEarned=570；启动时离线结算写失败后冻结。连续读取失败不改变完整冻结状态/诊断会话，不隐藏重试，也不显示“已恢复”。恢复存储后，手动/自动保存、招客、后台/可见、BFCache仍不能覆盖原字节。明确成功读取后才解除，重复相同端点不再领取。
2. 仓库直接调用：离线写失败 → 读取失败 → 存储恢复 → save初始状态，仍失败；成功load后才允许save。最后保存时间不因时钟倒退下降。
3. 启动暂时读取失败不能运行/购买/保存，重试为有效档后恢复。首次确实空白可直接新店；读取失败后发现空白或现有档消失属于missing，不自动初始化。
4. 当前有效店遭遇坏档/未来版本/缺失，失败恢复保留完整内存状态及保护。坏档原字节与有效当前副本均能单独导出，按钮名称明确；不可读启动的占位状态不能导出成进度。
5. 明确新店有独立确认，取消不改变任何状态。存在原档时先保留原字节备份；备份写失败、移除失败、重置前其他客户端换档都不能解锁或改写。成功重置才采用初始状态并重置时钟/呈现历史；缺失时不声称已经备份不存在的档。
6. 原有手动暂停档零离线收益后只恢复当前营业；冲突仍保护。与已有CAS/一次性端点/后台事件/单RAF/画面档位测试共同全量回归。
7. Mac真实浏览器更新另行操作，先确认当前树/分支和未提交工作，再使用精确已验证任务提交；不清空存储、不合入其他离线策略、不用日常存档制造故障。真实弹窗/下载/恢复可用性与像素验收单独记录。
