# TC-3D-017 · 连续离线时间与一次性升级边界

- 需求：REQ-3D-027、REQ-3D-006/007。
- 优先级：P0。类型：核心/持久化/应用handler；真实浏览器另验。
- 前置：固定时钟、独立内存存储，准备已有升级、在制咖啡、步长余数和经理在途现金的有效档；不触碰用户存档。

## 步骤与预期

1. 新策略分别隐藏或关闭0、0.01、29.9、30、30.1、7200秒，比较返回和重开。两种方式全部等于源状态分别推进0、0.005、14.95、15、15.05、3600秒；30秒附近没有跳降，超2小时不额外推进。
2. 100次0.01秒直接离线、300次10ms重开，保留合计余数；超过256条领取历史后旧端点和同端点仍不重领。
3. 无标记与v1旧档分别在0、29.9、30、30.1秒恢复。原未付区间按旧规则一次结清，信封v2与时间同时落盘。再过29.9秒使用新区间14.95秒，已有价格/等级/制作快照不追改。
4. 旧档处于0、短间隔、回拨或暂停时模拟quota失败/写前并发更新：原档或胜出档完整保留，无marker提前落盘；重试可以完成一次升级。非法marker不覆盖，未来marker保留。
5. 准备即将存款的经理，隐藏29.9秒后注入quota失败或另一个窗口写入：窗口保留切后台前状态，仅技术暂停，无成功收入提示；普通帧、手动保存、重复pageshow不能解锁。明确读取最新档成功后只补一次。
6. 隐藏时保存失败、返回时恢复写入：已有前台尾段不丢失，只补真实隐藏区间。持久化时间在未来时，返回不得补发未来端点之前的时间。
7. 连续/重复visibility与pageshow/pagehide排列保持一个RAF；重复回调不重领，回到前台后的新尾段仍按全速推进。
8. 最大合法CAS标签不造成超长领取ID；强制生成ID碰撞时安全拒绝，不写结算端点。暂停与超长间隔不改变上限或资产守恒。

通过条件：所有精确模拟断言、既有坏档/CAS/迁移/资金链/渲染回归通过。小数时间容差只用于浮点表示，金额与离线来源字节严格比较。测试在模拟时间完成；真实browser/pixels、跨进程原子CAS和CloudKit不由这些断言证明。
