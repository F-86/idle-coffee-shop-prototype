## 本轮修复的审查发现

- 导出深冻结不能连带冻结调用者的overview对象；改为完全脱离的摘要/状态。
- 替换结果不确定时，不仅普通保存冻结，重新导入也必须等到成功读取当前持久内容后再预览；失败读取不能解除此屏障。
- 导出要求本次明确保存成功；不能因为内存恰好等于旧持久状态而把写失败误作成功。
- 失败替换已经验证过的备份在当前页面仍能读取导出；成功导入的备份指针跨刷新保持。
- 未存盘当前快照的恢复导出使用新身份/revision1，避免重复使用旧持久身份下同一个修订描述不同状态；重复下载保持同一个已准备快照身份。

## 仍然适用的限制

1. localStorage字节比较不是原子CAS；要求关闭其他游戏窗口，仍无法证明挂起旧页面不会并发写入。多写者严格一致性不在本版范围。
2. 失败尝试的临时备份指针仅在当前页面保留；成功导入的最近备份指针持久化。备份记录不自动删除，配额不足拒绝导入。浏览器数据清除会删除本地备份，因此重要副本应下载保存。
3. 预览不写暂停标记。正常取消/隐藏不会补算预览等待；进程被强制终止时，后续仍从最后持久锚点按已有离线规则恢复。
4. SHA256只做完整性检查，不认证文件来源。下载/分享流程返回不证明文件已经保存或iCloud到达。
5. 普通原始/当前恢复导出继续保留，但旧恢复JSON不属于新可导入文件协议。正式文件导入不补发导出到导入间隔收益，UI在确认前明确告知。
