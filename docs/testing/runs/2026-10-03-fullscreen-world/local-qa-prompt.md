# Mac focused QA：全屏店面方向

只测试咖啡项目，不修改代码/main/部署配置。正常fetch codex/light-3d-coffee-slice，并核验父任务给出的最终SHA。在当前任务现用目录/独立worktree运行，不能猜历史Mac路径。有未提交修改则先保留。

1. npm ci；node --check app.js；npm run typecheck；npm test；npm run build。
2. 独立origin：npm run dev -- --host 127.0.0.1 --port 4184，打开 http://127.0.0.1:4184/?qa=1。不要复用旧方向截图的端口/存档。
3. 最先拍真实scene-fill截图，页面不滚动：1280×900 desktop、390×844 portrait、844×390 landscape，记录browser/DPR/100%缩放、实际canvas rect。每张必须覆盖整个viewport，HUD浮在店内，不能看到旧网页页头/外边框/下方经营卡片/侧栏。
4. 初始画面有可操作的大柜台，背景是连续房间地面/墙体，避免缩小的置中地台或首屏大片空白。竖屏看局部且可拖动；横屏没有被网页头部挤走的场景。截图不能只拍局部canvas。
5. 拖动到两款墙面咖啡牌、墙上金库、柜台配方牌/升级牌、入口与经理。检查浮动触控牌对齐物件、无重复DPR偏移、边缘裁切不可点；设置中的逛店导航可回到每个目标。辅助只读 window.__coffeeSliceDebug.readAnchors() 可记录位置，不准通过业务函数改变结果。
6. 至少一次从投影DOM控件本身开始拖动、长按800ms以上、拖出后返回、取消/二指。不得误开窗口或招客；有效短点只触发一次。画布和控件拖动共用受限镜头，不能拖进空场景。
7. 点墙上菜单→查看/分配到柜台→关闭；点柜台配方牌→换配方/买一次升级→关闭；点金库/经理查看与升级。按需窗口必须只显示当前内容，无常驻经营面板。关闭×、Escape、点击背景均回店，窗口内部空白不误关；窗口遮挡时背景不能交易/平移。
8. 键盘Tab/Enter验证控件与窗口，金库→经理切换后焦点可见；关闭移动/被裁切的经理窗口可落回设置，不留焦点在隐藏物件。窗口内滚动不平移店铺。
9. 地址栏尺寸变化、旋转、safe-area后canvas仍满viewport，HUD/窗口/44px触控目标不挤出边界。暂停/恢复、刷新、Back/Forward仍正常。确认本地自动档且iCloud未配置。
10. 真实UI营业90秒检查完整资金链，38项云端CPU/结构测试不替代此玩家路径。

返回：最终SHA、每项PASS/FAIL/BLOCKED，三张scene-fill真实截图，以及至少一张按需窗口和关闭后截图。若外观仍留白、比例或操作嵌入不对，请直接给最短复现与截图，不能因“canvas100%”而标方向通过。
