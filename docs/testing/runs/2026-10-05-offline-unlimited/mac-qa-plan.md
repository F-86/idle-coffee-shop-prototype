# 有界Mac预览验收计划（尚未执行）

目标：验证精确交付提交在真实浏览器中的进度/取消/结果、存档安全及保留场景。不是主分支发布或部署授权。父任务另行协调；本云端任务未访问用户Mac。

1. 先检查Mac现有分支/HEAD、工作区修改、正在使用的4180服务来源；不得覆盖未提交修改或清理日常localStorage。核对交付远端完整SHA/tree。正常fetch后建议单独worktree和独立端口（例如空闲4182），不要先替换4180。
2. 使用全新测试浏览器上下文/明确独立origin。打开 `?qa=1`，确认scene、金库靠近/地毯完整接角与清晰60帧选择仍在。桌面和窄视口各一张真实截图；帧率/温度不凭肉眼或cloud日志推断。
3. 只在独立测试origin准备合法合成新店存档：v3、当前schema/routes、固定recordChangeTag、savedAt为真实当前时间减3小时。不要改OS时钟或使用用户日常存档制造故障。预存原字节并记录wallet、totalEarned、pending、carrying。
4. 重开：观察可取消进度（含金额未先到账）；真实点击取消/关闭/Escape，检查原存档与原钱包不变。设置中重试，等待一次完成；结果显示80%有效时间、实际入库、生成和未入库款，和核心参考比对。截进度及结果，记录real elapsed；3小时通常只需数秒计算，不要求真等3小时。
5. 重复读取/刷新同端点，检查不重复领取；在结算过程中切后台再回来，测试重复visibility/BFCache恢复不回退、只有一个RAF。两窗口在测试origin更改存档以验证冲突保护，不对日常origin操作。
6. 使用同一合法快照的无标记/v1和v2合成旧档，检查原50%/2小时一次结算说明；下一段新离线按80%。少于30秒的v1旧区间仅迁移、不补收益；v2短区间按50%。原始内容故障/写入故障只可在测试存储中注入，取消后能导出当前有效副本，失败不新开店。
7. 真实短离开约30秒，核对展示与存档端点/固定余数；不是要求钱包逐秒平滑增长。经理入库可能包含之前现金，截图文案不得把它全称新增营业额。
8. 异常长前台无回调空档的保护已在handler harness覆盖。若在测试环境进行调试器暂停测试，超过60秒应保护冻结，不改成2小时上限；已知正常持续计算等待不误冻结。不要为了此项改变用户系统设置。
