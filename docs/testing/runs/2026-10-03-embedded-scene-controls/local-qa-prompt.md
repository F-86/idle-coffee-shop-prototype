# Mac focused QA：实体入口与金额唯一HUD

只测试咖啡项目，不能改main/部署配置。正常fetch codex/light-3d-coffee-slice并核验父任务提供的最终SHA。在已存在任务目录或独立worktree中运行，不猜路径；有用户改动先保留。

1. npm ci；node --check app.js；npm run typecheck；npm test；npm run build。
2. 独立origin：npm run dev -- --host 127.0.0.1 --port 4185，打开 http://127.0.0.1:4185/?qa=1。隔离之前4184测试存档，不改用户日常档。
3. 先拍完整viewport真实截图：1280×900 desktop、390×844 portrait、844×390 landscape。记录SHA、browser、DPR、100%缩放和canvas rect，并区分桌面触控模拟与实际iPhone/iPad设备；不能将缩放viewport写成真机通过。每张店铺满屏，永久HUD只有清楚的¥金额；没有DOM浮动按钮、暂停/设置HUD或悬浮进度/台面金额。
4. 咖啡墙、金库、营业/设置实物、柜台配方/升级牌、入口招客和经理推车的文字必须贴在物件面上，随面透视缩短、光照及遮挡。不要接受“worldanchor跟随DOM”或总在最上层的字卡。柜台和墙面中文/英文须真实可读；必要时给近景截图。经理推车为固定世界方向实物，经理转身不会让宽车绕进柜台/墙体；本轮为容纳真实44px操作牌扩大车体，务必检查与人物、柜台、服务通道的比例，以及纸牌不遮现金。
5. 从各实体短点，验证相应弹窗或营业切换一次。金额区域仅显示；点击/拖动金额不得透过HUD触发背后实体或拖动相机。拖动到全11个入口，手机几何点位够大，墙牌不被不合理灯具盖住。只读 window.__coffeeSliceDebug.readAnchors()/focusedObject()可记录，不用业务函数改变结果。
6. 从实体牌上开始拖动、长按>800ms、拖出回原点、取消/二指；不误开窗/招客/暂停。经理移动过程中按下后目标离开，不激活另一物件。人物/家具遮住部分牌时，点击遮挡前方不能穿透触发后面。请保存遮挡行为的截图/短复现。
7. 菜单→分配→关闭，柜台配方→改配方/升一级→关闭，经理升级/金库，营业牌暂停/继续，设置物件打开本地设置。可见键盘焦点；×/Escape/背景关闭，内部空白不关闭，弹窗背景不能拖动/交易。
8. Tab到canvas，左右选择真实物件，上下平移，Home回A，Enter/空格激活。按住Enter只一次。金库→经理切换关闭后焦点回canvas；上下导航/关闭无隐藏焦点。物件名提示瞬时，不常驻HUD。
9. 地址栏/旋转/safe-area后仍满viewport，横屏pan可达墙牌，不缩成小场景。刷新、后台/回前台、Back/Forward和暂停恢复；UI明确仅本地/iCloud未配置。真实营业90秒完整入店→排队→制杯→台面钱→经理→金库链。

返回最终SHA、逐项PASS/FAIL/BLOCKED、3张scene-fill新截图、实体近景和至少一个弹窗/关闭后截图。若外观文字小、方向不融入或点击被意外挡住，直接FAIL并给最短复现，不把NullEngine结构通过写成真实视觉通过。
