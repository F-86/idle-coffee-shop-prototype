# AI 集成测试执行规范

## 执行前

1. 阅读计划、关联规格、用例和共享数据契约；固定本轮用例清单及参数。
2. 记录 commit、dirty 状态及相关补丁/文件指纹、规格版本、时间与时区、URL、浏览器版本、视口、缩放和输入方式。
3. 使用独立测试上下文或 origin，确认不会误操作日常存档。按 [准备流程](shared/setup.md) 初始化。
4. 确认页面可用及关键资源加载。无法启动记环境阻塞；确认是产品启动故障则记产品失败。

## 执行中

- 通过 UI 完成被测业务。Browser-Use 优先可访问名称或稳定标识；Computer-Use 每次根据最新截图定位，不能复用页面变化前的坐标盲点。
- 点击后等待用例指定状态，记录实际等待时间。测试预算超时先区分产品超时和无法观测；不能无限等待。
- 前置数据注入、时间模拟须在计划允许范围内，记录方法和数值；不得直接修改待测结果或调用业务函数来声称 UI 已通过。
- 金额比较记录前值、后值和所有并发收支。无法排除后台生产、经理入库、奖励时，不把余额差直接归因于本次动作。
- 涉及时间时记录开始/结束时刻、页面可见性、真实或模拟时间。后台标签页不等同关闭页面；禁止修改系统全局时钟来准备测试。
- 数值显示可能舍入。精确金额断言须使用规格规定的精度及可观测读数；只看到缩写金额不足以判定精确计算通过。
- 控制台、DOM、网络、存档只作为工具支持时的辅助证据。纯 Computer-Use 获取不到时写明限制，不伪造日志；必需证据不可获取则 BLOCKED。

## 失败与重试

先保存失败现场，再做诊断。默认最多进行一次独立重置后的复测；不能反复点击直到成功。两次结果不同记 FLAKY，稳定违反规则记 FAIL；工具误点需保留记录并说明无效尝试原因。

缺失的已确认功能记 FAIL/未实现。规格尚未确定时记 BLOCKED/规格缺口。已知问题也保留本轮证据，不静默跳过。

## 证据与收尾

运行目录命名 `YYYY-MM-DD-HHMM-plan-name/`；按用例和尝试编号保存截图、操作记录、可用日志及必要状态摘要。每条断言记录实际读数，关键步骤前后截图；动态循环需要时间序列，单张静态截图不证明完整循环。

完成后执行清理，填写报告与缺陷链接，披露所有未覆盖项。报告区分“执行/报告完成”和“版本验收通过”。测试途中修改了代码或规格，必须开启新的版本记录并重跑受影响项。
