# 无时长上限、80%离线经营计划

2026-10-05 UTC。用户最新要求为「上限还是不要改成30分钟了，无上限，效率改成80%」。替代此前研究的30分钟候选；该候选从未作为已发布策略写入存档。对应 REQ-3D-030 / TC-3D-020。

## 基线与范围

以 `8a8ea9767529b7deeeaf45a4aed20978a82284e4` 为基线，新分支 `codex/offline-80pct-unlimited`。保留 a6 场景接角/金库间距、b1 清晰60帧与失败恢复写屏障；整合另一分支的短离线一致性，不带回它的旧场景。只改离线策略、精确长区间调度、事务迁移、相关UI与验证。无其他调价、自动升级、付费、云同步、main合并或部署修改。

## 独立预期

1. v3有效经营秒数 = 非负真实离开秒数 × 0.8；没有30秒门槛、2小时或天数上限。制作/经理运输照常逐步执行，钱实际送入金库后才能花；价格与在制杯快照不变。
2. v1（无标记或1）现存区间：不足30秒不推进，否则 min(秒数,7200)×0.5。v2：所有正区间 min(秒数,7200)×0.5。各自最多按原规则结算一次，状态、v3标记和不倒退的时间锚点同一写入生效。写失败、CAS冲突或取消不能消耗区间或标记迁移完成。
3. 分批计算只改变执行调度，不改变模拟。固定步总数/余数先计算一次，每批整数步；32步小批，每轮目标8ms后用宏任务让出主线程。进度按完成时间而非预估钱显示。生产/经理/资金总账与一次性同核心参考完全一致。
4. 长计算在独立候选引擎内完成，当前店冻结而不显示候选钱。最后才比较原存档字节并一次保存；以原始字节、代际和任务身份抵御过期异步完成。取消/隐藏/销毁/新读取/冲突使旧完成失效。相同有效未保存现场的取消/失败重试由严格匹配快照、起点和原字节授权，不放开普通保存写屏障。
5. 正常前台计算等待时间从请求端点起按在线时间计入，不把完成时刻直接写成未计算的锚点。中途隐藏则取消并保留完整待结区间。暂停旧档先零推进结算，再恢复当前无暂停UI营业。
6. 无玩法时长上限不代表无限数值：沿用存档上限模拟时钟4,000,000,000秒、主要整数资产/事件/顾客编号1,000,000,000,000；时间戳0至8.64×10^15毫秒。不可表达、非有限、无效状态拒绝且保留原字节/未领取区间，不截断、不舍弃、不直接补发钱。暂停区间无需模拟，因此不能被运行时长预检错误拒绝。
7. 用语区分：已存入金库=钱包增量（可能包含原待收款）；新增营业额=totalEarned增量；待收/运送中为期末余额。旧策略一次性结算说明真实旧比例/上限，不把旧档这一段说成80%。

## 验证

- 精确边界：0、29.9、30、30.1、1799.9、1800、1800.1、7200、7200.1；分段与随机整数步批次；已有杯/配方/现金、低等级经理瓶颈。
- 迁移：真实合法v1/v2快照、零/短/长/暂停/回拨、最大合法标签、重复端点、迁移写失败重试；未来v4保留原档。
- 故障：分批中取消/抛错、最后quota、并发换档、同实例更新读取、重复finish、删除/坏档、ABA字节恢复、技术暂停与无效占位保护。
- 实际main handler：进度/取消/重试、不可投机显示钱、短区间同步失败、隐藏/BFCache/重复恢复、页面销毁、storage事件、最新读取胜出、计算前台尾部与单RAF。
- 合成7天/30天完整回放记录真实云端耗时、yield数、客户/存档大小、资金守恒。不是Mac速度、视觉或功耗结论。
- 语法、typecheck、全部测试、默认和原Pages路径构建、独立审查；真实Mac另由父任务协调，先保留用户现场再更新精确提交。

## 非离线的异常前台空档保护

本轮不扩大成在线时间债务系统。若没有hidden等可信边界却出现超过60秒的未说明前台RAF/保存尾部空档，冻结并保留内存/原档，提示导出当前副本或明确读取最新档；不静默截断、改按80%或自动覆盖。这是异常恢复边界，不限制已确认后台的离线时长。逐次回调连续观测的正常异步计算等待是已知的前台时间，必须排除在此异常判断之外并按在线速度推进；购买/换配方/招客前先推进，不能把新操作追溯应用到计算等待期间。
