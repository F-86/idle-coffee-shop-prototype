# 独立文件探针测试计划

对照 [REQ-FILE-001–007](../../product/specs/icloud-file-probe.md)。实现和执行证据分别维护；纯逻辑测试不证明原生文件选择器或 iCloud 同步。

## 必须独立完成的真实 UI / 系统用例

**TC-FILE-014 界面与中断：** 桌面与窄屏显示全部文字/完整 hash；初载没有权限提示；生成后导出按钮可用；反复点击不并发发起操作。打开通用选择器后取消，确认内容未变、能再次选择同一文件。导入坏文件后原合法内容仍在。刷新/Back/Forward 后不得以旧基准自动报告成功，也不得自动读文件。记录浏览器版本、origin、secure context、设备与截图。

**TC-FILE-015 Chromium 本机往返：** 在独立测试位置生成并保存新随机名称。若出现权限选择，只允许本次该文件。记录 save 后逐字节读回及完整 hash；尝试选已有非空测试文件，必须拒绝覆盖，原字节不变。取消/拒绝后内容未丢失。任何持久授权如不可避免，停止测试并另行确认。

**TC-FILE-016 Safari 基础路线：** 记录实际 API 能力，不预先假设增强选择器存在。生成 JSON 并下载；手动确认 Safari 保存位置。通过通用输入从 Files/iCloud Drive 选回副本，核对 ID/revision/hash。可选分享仅在按钮可用时测试；分享成功不能写“iCloud 已同步”。

**TC-FILE-017 双设备正向：** 设备 A 导出新副本到其系统可见 iCloud Drive 测试位置；设备 B 在自己的独立测试页通过其文件选择器选该文件；两端人工核对同一 probeId、revision 和完整 SHA-256。记录两端真实 UTC 时间和系统位置证据。此时只记录“跨设备文件已到达”，不宣称自动/实时游戏同步。

**TC-FILE-018 双设备反向：** B 在已验证的合成文件上 revision +1，另存新随机名称；A 选择新文件，核对 probeId 相同、revision 恰好 +1、新 hash 与 B 一致，旧文件未修改。不同修订不能被报告为旧修订往返通过。

**TC-FILE-019 不可用与边界：** 在实际无增强 API 的环境验证基础按钮；非安全上下文不报 hash 校验通过；16 KiB 超限、错误版本、游戏存档名称、恶意文件名均拒绝。实际 iCloud 未配置/网络未到达时记录 UNKNOWN/BLOCKED，不伪造成功。

手工测试只使用合成文件。未执行的项标 NOT_RUN，平台限制为 BLOCKED。跨设备测试页可用性是单独前置条件；本任务不新增托管或修改现有 Pages。
