# 同类家具库存验证计划

REQ-3D-043；[TC-3D-030](../cases/slice/TC-3D-030.md)；2026-10-05 UTC。基线 `af38c0b1aac4055b63316836d06d0f2330413c5d`。

## 独立预期与数据

- 使用隔离 origin/profile 和合成档，不修改日常小店。预置余额、拥有实例与合法坐标，不通过生产入口加钱。
- 场景一：至少一台柜台保持放置，另有两台可用柜台和两套可用桌椅；分别记录 IDs、等级、配方、亲和效果、生产数、钱包、支出和保存字节。
- 场景二：A/B 同等级、同配方但固有亲和效果不同；再以等等级/等配方的 C/D 验证无实际差异时的简化选择。
- 场景三：没有可用库存、余额不足、拥有量达上限，以及已付款库存和待购库存并存。预期来自规格与预置资产清单，不能直接复用实现选择函数生成答案。

## 自动化层

1. 分组和库存：每类唯一图片卡；全部/分类/收纳一致；已拥有、已放置、可用、待购语义分明；合法放置按 2→1→0 递减，收起按 0→1 补回。仅选择、无效拖放和取消不消耗库存。
2. 购买门禁：非零库存不能购买；零库存卡主体/拖动不购买，仅明确价格按钮创建一个收纳的待购实例，计数变为一且入口消失。重复/过期点击不得多添置，余额与容量门禁仍生效。
3. 身份选择：有实际差异时选择指定实例；无差异时稳定自动取一件；已付款可用实例优先。A/B 的固有亲和效果不能因同等级/同配方被忽略。移动、旋转、收起/放回、提交和读回保留完整身份及升级。
4. 事务：放置已有物件免费；待购项只在完成时扣一次，未放置的待购项也按明确购买计入总价；取消单项移除该费用。取消全部、两层 Escape、隐藏/离页、存档冲突、非法布局和重复完成继续使用已有保护；取消后已提交状态与资产清单一致。
5. 输入：实际应用 handler 的点击、拖拽、拖后 click、迟到 pointerup、pointercancel、lostpointercapture、blur、触屏横滑和次要指针；控制组保留键盘/按钮替代路径。模拟 DOM 只证明事件与状态契约。
6. 回归：`node --check app.js`、`npm run typecheck`、`npm test`、`npm run build`，独立 file-probe 类型检查/测试/构建、既有 Pages base 构建和 `git diff --check`。原布局/经营、原料、持久暂停、离线与手动文件安全用例保持。
