# 存档恢复失败保护计划

2026-10-05 UTC；基线 a6e2bbb01860fcd5730d48ea229def870f1b3e79，分支 codex/save-recovery-safety。对应 REQ-3D-029 / TC-3D-019；用户授权修复已复现的存档恢复保护问题。

1. 先用隔离内存存储和实际 main.ts handler 复现：合法旧店 totalEarned=570，启动离线端点写失败 → 读取最新档时 getItem 暂时抛错 → 存储恢复。基线会把初始店 totalEarned=0 当作恢复结果、解锁并允许覆盖。禁止访问或故障注入用户日常浏览器存档。
2. 恢复只有完整 loaded 结果才可替换当前引擎和解除保护。缺失、读取不可用、坏档、未来版本、CAS冲突和离线端点写失败保持当前内存副本/冻结。首次读取确实为空可正常新店；恢复时为空只能明确确认新店。
3. 仓库增加失败读取后的写屏障。只由成功读取/结算或明确重置解除，不因浏览器存储恢复而自行开放。保持原CAS比较、原始坏档导出、本地备份先于移除、非倒退保存时间和一次性结算。
4. 独立验证取消/重复恢复、备份写失败/移除失败、并发替换、后台/BFCache/自动保存/销毁、已暂停旧档、回拨时钟；恢复时不能将不可读占位状态导出为有效进度。坏档和被保留的有效当前副本分别提供清楚的导出入口。
5. 全量测试、语法、类型、默认和既有Pages路径构建、diff检查及独立只读审查。此分支不合入另一分支离线策略、不改收益上限/效率、场景/画质、工作流或部署配置。
