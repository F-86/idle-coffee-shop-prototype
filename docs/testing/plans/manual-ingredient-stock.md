# 手动原料验证计划

关联：REQ-3D-040–042，TC-3D-028。与实现独立核对需求，不以自动化结构测试代替浏览器像素或触控验收。

## 核心、保存与重放

- 原子配方检查、最后一份竞争、拿铁缺奶不误扣豆，水免费。
- 缺料分配过滤；在途杯保留快照，待制作客空手离店、正常收款不重复，暂停清场进入装修。
- 一份、一批、补满及临近容量；不足款整体拒绝、重复点击、非法参数、暂停购买、离线候选阻止可变操作。
- 配方变化、升级、每步刷新、批量离线、不同步分区的库存/钱包/总收入/消费/顾客一致。
- 库存不足的长期离线自然停产、时钟保持80%且无额外时长上限；暂停零消耗；无自动采购/免费救济。
- 当前库存边界、版本配对、字段缺失、旧版本与库存字段不匹配失败关闭并保护原始字节。
- 经济1–4旧在制杯和未结算区间，旧策略1/2/3既定输出的冻结夹具；只初始化一次，失败、取消、CAS和成功重读不重复种库存或收入。
- v5文件往返、旧文件迁移预览、重复导入、备份库存和导入后区间零收益。

## UI与真正浏览器

- 五个带图图标在窄屏不溢出；原料卡份数/容量、实际报价和可购状态正确。
- 单次购买、补满报价随经营消耗变化、连续点击、库存已满、余额不足、暂停营业、文件预览/切后台/离线/失败保存保护。
- 缺奶提示可改浓缩；零豆零资金无在制杯时显示阻塞原因，未承诺自动救济。
- 离线面板时间+净余额变化+缺料提示；文件预览/导出/导入显示库存。
- 使用独立origin/测试存储验证，不能修改日常存档。实际GitHub Pages部署与云浏览器验收由父任务在验证分支之后独立执行。

## 最低提交检查

node --check app.js；npm run typecheck；npm test；npm run build；子路径Pages生产构建；根路径与Pages路径的版本探针测试；独立代码审查。报告应注明版本、环境、时间口径、PASS/FAIL/BLOCKED/NOT_RUN和证据。
