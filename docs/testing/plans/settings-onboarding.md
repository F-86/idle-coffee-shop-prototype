2026-10-05 UTC；SETTINGS-QA-1.0；REQ-3D-034 / TC-3D-024。

## 自动化

使用真实 main.ts handler、真实引擎/保存仓库和模拟DOM/场景。新测试校验节点祖先可见性，不能通过点击隐藏按钮冒充恢复入口可达；模拟原生details及hidden反射，但不声称替代浏览器。四档画面、保存/恢复/导入导出、重复输入、暂停、销毁、离线一次性、坏档及冲突继续运行全套回归。单独比较有/无引导的在线/离线业务状态，随机领取ID仅在跨实例比较时规范化，同时校验每实例领取次数及已保存一致性。

运行 node --check app.js、npm run typecheck、npm test、npm run build，以及既有Pages路径构建、file-probe类型/14测试/构建。独立审查后再次检查最终代码。报告分别记录PASS/FAIL/BLOCKED/NOT_RUN及源码SHA-256。

## 独立浏览器/真机最小清单

使用独立端口/origin和合成数据，确认交付SHA，不触碰日常小店。不得合并main或部署来代替本地QA。

1. 全新origin，1440×900及390×844：引导四步的实体焦点、短文、下一步/跳过。完成、跳过和中途刷新各用独立origin验证，均不能自动重播。用已有发展档启动不弹引导。
2. 打开设置：只见收起的画面和小店存档。鼠标/Tab/Enter/Space展开收起画面，四种模式切换后关闭、返回、刷新仍正确；不改变经营速度。
3. 存档页：自动保存说明/状态、保存进度、导出与导入顺序明确；正常时没有恢复卡。生成→下载，选择文件→取消/重选→预览/确认→找到导入前备份。原生选择器与分享面板另行验证，不把“已发起”当作云端到达。
4. 故障合成origin：坏档/未来档/读取失败/空间不足/缺失/多窗口冲突。设置入口有提示，进入存档后立即能看到相应恢复操作；原始字节和有效副本不混淆，失败不解锁。取消新店/读档确认保持进度，成功恢复后卡片消失。
5. 引导期间打开设置、咖啡或金库，再关闭/Escape；引导步骤不重置。Tab不落入隐藏按钮。导入或接受另一个窗口进度后不会恢复新人卡片。测试隐藏/恢复、短离线结果和BFCache，经营结算不被引导阻挡。
6. 320×640及844×390：卡片/滚动/44px点击区域、长故障文案和导入预览，不出现横向溢出或无法关闭；场景目标不被短卡长期遮挡。屏幕阅读器只在步骤变化时播报，不随每帧重播。

若受支持云浏览器拒绝localhost，记录BLOCKED，不更换地址、代理或浏览器绕过。Mac、手机、Safari未运行明确NOT_RUN。
