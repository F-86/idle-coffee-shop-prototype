# 清晰60帧选项计划

2026-10-05 UTC；基线7d41984；REQ-3D-026 / TC-3D-016。

目的：保留smooth的清晰度，给高刷新屏提供60fps提交上限，避免必须降分辨率才能限帧。只加独立选择，不改变默认和已有偏好，不调经济参数。

## 实现与自动化

- 在已有RenderBudget配置新增clear-60（60 / DPR2 / 800万），复用当前时间尾部、丢帧与生命周期逻辑；不改20Hz核心、插值和保存。
- 设置新增原生选择按钮及清晰说明，四项两列排列，aria-pressed和分组描述同步；现有独立偏好key继续使用。
- 扩展多刷新率、所有画质经营一致性和NullEngine模式用例，另建清晰度等值、切换尾部、旧偏好/现有存档、持久化失败、QA新段用例。新增6项TC-3D-016先在基线上确实失败，再实现并复测。
- 语法、类型、全部测试、默认和既有Pages路径构建、独立审查通过后，只正常推既有任务分支。main、工作流、部署和依赖不变。

## Mac对比交接

沿用[帧节奏测量计划](performance-measurement.md)的环境、独立存储、完整冻结文本和统计范围要求。本项只新增三段smooth→clear-60→smooth；旧balanced/low-power数据不重命名为新选项数据。

1. 确认最新精确commit与实际加载资源hash；本地独立origin，不覆盖日常存档。记录浏览器版本、实际CSS viewport、设备DPR/缩放/pan、等级/配方/客户阶段/mesh和core elapsed，保持经营弹窗关闭。
2. 三段各预热至少30真实秒，再重新计时。采样段“本段”至少60秒，无模式/尺寸/焦点重开；记录整份冻结文本和真实起止时刻。最后smooth是顺序对照，不把自然经营造成的负载变化当严格相同状态A/B。
3. 三段实际buffer应相同，clear-60 target应60；只有显示刷新高于60Hz时预期提交FPS明显下降。p50/p95属于最近10秒窗口，累计FPS/长间隔属于整段，按原字段分别记录。
4. 用键盘/鼠标切换、重复选择、关闭/重开设置并刷新，确认持久化和同等清晰度；检查两列设置在实际窗口不裁切。用场景相同字牌/镜头截图检查可读性，不能只用理论DPR判像素PASS。
5. 历史后台工具未能充分触发事件，本任务不盲目重复该实验、不另加生命周期台账；已有自动化保持。若另做后台项，必须留实际hidden/focus证据，否则INCONCLUSIVE。

性能仪表记录的是RAF渲染提交间隔，不是GPU完成、上屏帧、负载、功耗或温度。无传感/系统测量则相应项NOT_RUN。云端无法真实像素验收时明确未完成并交由已授权Mac执行，不绕过浏览器安全限制。
